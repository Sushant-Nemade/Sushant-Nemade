# Option 2 Plan: Applied AI Dossier

## Direction

Option 2 presents the profile as an evidence-oriented professional dossier. It keeps the verified content from `config/profile.json`, replaces the terminal treatment with numbered sections, and uses a restrained coral accent across self-hosted graphics.

## Structure

1. Theme-aware dot portrait and locally generated animated identity banner
2. Concise positioning and professional links
3. Focused capability toolbox
4. Profile-emphasis radar derived from configured capability breadth
5. Public-repository language signal based on GitHub data
6. Theme-aware contribution activity and compact public statistics
7. Four case-study cards using the existing verified project descriptions
8. Experience, education, principles, and contact

## Reliability

- Core graphics are committed under `options/option_2/assets/`.
- Every theme-sensitive visual has dark and light variants selected through `<picture>`.
- SVG animation is progressive enhancement; useful content is visible without animation.
- No third-party profile-statistics, badge, font, or analytics service is required.
- Public GitHub metadata can be refreshed by a manual-first workflow.
- Option 1 remains available in `README.option-1.md`.

## Honest-data decisions

- The capability radar measures relative breadth of configured capability lists, not proficiency.
- The public repository language panel uses observed public repository bytes. With the currently visible repositories, Python is the only detected language, so a fabricated multi-axis radar is deliberately not used.
- Contribution totals are omitted when GitHub's public markup does not expose complete exact counts.
- Case studies without public repositories remain visibly marked as in preparation and are not given fake links.
